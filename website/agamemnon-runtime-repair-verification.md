# Agamemnon functional layout repair — verification

This follow-up is based on merged PR #42, not an update to that PR. The ordinary Odysseus theme remains the comparison surface.

## Reproduction and repair

The production theme cascade previously forced every Workbench secondary panel into view, even when its tab was inactive, and positioned the Chat composer and transcript independently of their native scroll container. Narrow widths then clipped Agents cards and pushed controls outside the viewport. The fix keeps Chat's native transcript/composer ownership, lets Workbench's own tab state decide panel visibility, restores reachable Agents detail and appearance selection, and scopes all reflow/contrast changes to `html[data-theme="dark"]`. No new static-only UI replaces a control.

## Browser evidence

`tests/test_agamemnon_runtime_layout.py` starts the actual `static/index.html` and JavaScript against a representative local API stub and drives Chromium through its native DevTools protocol. It checks 1440, 1280, 1024, 390 and 320px; the fixture contains a long transcript and code line, three agents and a run timeline. Checks cover actual bounding boxes, horizontal overflow, transcript scroll, typing and send-request dispatch, selected session/model/status, agent card selection and visible detail, parent appearance save/reload through the API stub, Workbench navigation/tabs/dock/close, theme switching, and ordinary Odysseus rendering. A failing production CSS cascade caused the initial browser checks to fail before the repair. The fixture is deliberately not an LLM, database or real durable-run service: send verifies request dispatch, not an AI response or backend delivery; appearance reload verifies the browser/API contract against stub storage, not the deployed database. No server-backed live-app end-to-end test was available in the sandbox.

Screenshots from the **actual production HTML/CSS/JS running in Chromium against that stub**, not hand-authored page previews, are in `website/agamemnon-runtime-evidence/`: `chat-{1440,1280,1024,390,320}.png`, `agents-{1440,1280,1024,390,320}.png`, `workbench-{1440,1280,1024,390,320}.png`, docked desktop views, and ordinary `odysseus-chat-{1440,390}.png`. Screenshots are generated by setting `AGAMEMNON_SCREENSHOT_DIR=website/agamemnon-runtime-evidence` for the browser test. The 320px Agents screenshot exposed a child action overflowing its card; that was fixed with a wrapped child row and re-tested.

Penpot file `77fbae64-173c-81f5-8008-b823d468d03d`, page `b44baf9e-64a9-4d69-958a-d07e52b9d89b`: Chat `51e8f401-6310-4ca6-a1e1-a25037d25953`, Agents `21e06404-5496-43be-8a32-d1e65883ce31`, Workbench `e8977336-40b5-4f21-b5e8-65a4b27c6d6e`. The wide-screen graphite/brass hierarchy and side-profile helmet/role soldier assets remain; compact screens deliberately stack content to keep working controls. Penpot's viewer renders dark text on dark surfaces, limiting direct text/contrast comparison. The independent UI critic accepted the desktop/compact composition with changes and requested more real-service and accessibility coverage; browser testing and the 320px repair address part of that request, but do not substitute for a deployed-service audit.
